# Cursor AI Assistant Troubleshooting (Windows)

Этот документ помогает быстро диагностировать, почему AI-ассистент в Cursor может не запускаться, не отвечать или работать нестабильно.

## Когда использовать этот гайд

Используй, если:
- ассистент долго "думает" и не отвечает;
- запросы периодически падают с ошибками сети/авторизации;
- сегодня работало, а потом перестало;
- в одном проекте работает, а в другом нет.

## Частые причины

- Нестабильный интернет, VPN или прокси.
- Временные проблемы сервиса (инцидент на стороне провайдера моделей).
- Истекшая сессия в Cursor (нужно пере-логиниться).
- Лимиты аккаунта/тарифа или ограничения по использованию.
- Локальный сбой приложения Cursor после обновления.
- Фильтрация трафика антивирусом/фаерволом.
- Некорректные дата/время в Windows (ломают TLS/авторизацию).

## Быстрый сценарий (2 минуты)

1. Полностью закрой Cursor.
2. Отключи VPN/Proxy на 1-2 минуты.
3. Проверь интернет (открыть 2-3 сайта в браузере).
4. Запусти Cursor снова и повтори запрос.
5. Если не помогло — выйди из аккаунта и войди заново.

Если уже на этом этапе заработало, причина чаще всего в сети/сессии.

## Пошаговая диагностика

### 1) Проверка сети

Открой `cmd` и выполни:

```bat
ping 8.8.8.8
ping github.com
```

Что важно:
- `8.8.8.8` проверяет базовую доступность сети.
- `github.com` проверяет DNS + внешний доступ.
- Потери пакетов/большая задержка => вероятна сетевая причина.

### 2) VPN / Proxy

- Временно отключи VPN.
- Если используешь системный proxy, отключи и повтори проверку.
- В корпоративной сети попробуй домашнюю точку доступа (для сравнения).

### 3) Полный перезапуск Cursor

- Закрой Cursor.
- Открой "Диспетчер задач" и заверши оставшиеся процессы Cursor.
- Запусти приложение снова.

### 4) Переавторизация

- Выйди из аккаунта Cursor.
- Войди повторно.
- Проверь, исчезли ли ошибки авторизации/доступа к модели.

### 5) Обновление приложения

- Установи последнюю версию Cursor.
- После обновления перезапусти Windows.

### 6) Проверка времени в Windows

Путь: `Параметры -> Время и язык -> Дата и время`

- Включи автоустановку времени.
- Проверь корректный часовой пояс.

Некорректное время часто вызывает ошибки TLS/подписей.

### 7) Антивирус и фаервол

- Временно отключи web/https сканирование (если есть).
- Добавь Cursor в исключения.
- Повтори запрос.

Важно: после теста верни защиту обратно.

### 8) Изоляция проблемы

- Открой пустую папку в Cursor.
- Проверь, работает ли ассистент там.

Если в пустом workspace работает, проблема может быть в проектной конфигурации/расширениях.

## Признаки проблем на стороне сервиса

Обычно это:
- массовые сбои "у всех";
- ошибки появляются и исчезают сами через 2-10 минут;
- все локальные проверки нормальные, но ответа нет.

В этом случае:
- подожди 5-15 минут;
- попробуй снова без изменений локальной среды.

## Что делать, если проблема повторяется регулярно

- Зафиксируй, в какое время чаще ломается.
- Проверь, не включается ли VPN/Proxy автоматически.
- Сравни поведение на разных сетях (дом/моб. интернет/офис).
- Обнови драйверы сетевого адаптера Windows.

## Краткая памятка

- Сначала сеть -> потом VPN/Proxy -> потом перезапуск -> потом логин.
- Не трать время на глубокую отладку, если это массовый кратковременный сбой.
- Если  роблема держится больше 30-60 минут, собирай отчет и отправляй в поддержку.

***********************************************************************************

Ниже чек-лист под твой ноут (Celeron N3350, 4 ГБ ОЗУ, Intel HD 500, SSD ~224 ГБ). Учти: это слабая конфигурация — часть «проблем с ассистентом» может быть не сетью, а нехваткой памяти и тормозами диска.

1. Сначала проверь «железо», а не только ping
4 ГБ ОЗУ — для Windows + браузер + Cursor это мало. При нехватке памяти всё уходит в файл подкачки → зависания, таймауты, «не запускается» без явной ошибки сети.
SSD TR200 без DRAM — при заполненности и активной подкачке диск может сильно тормозить.
Что сделать:

В Диспетчере задач (Ctrl+Shift+Esc) → вкладка Производительность → Память: смотри, не упираешься ли в 90–100% при работе Cursor.
На диске C: оставь минимум 25–30 ГБ свободно (лучше больше).
Закрой лишние вкладки браузера и тяжёлые программы на время работы с ассистентом.
В Параметры → Система → О программе → Дополнительные параметры системы → Быстродействие → Дополнительно: убедись, что файл подкачки системный, управляемый Windows (или задай фиксированный разумный размер, если сейчас отключён — на 4 ГБ отключать подкачку нельзя).
2. Wi‑Fi и драйвер (типично для ноутов с N3350)
Узнай точную модель ноутбука (наклейка снизу или msinfo32 → «Изготовитель модели»).
Диспетчер устройств → Сетевые адаптеры → запиши название Wi‑Fi (например Intel Wireless-AC … или Realtek …).
Драйвер ставь с сайта производителя ноута под твою модель; если там старая версия — для Intel Wi‑Fi можно взять Intel (пакет для твоего чипа), для Realtek — с сайта Realtek/производителя.
Энергосбережение Wi‑Fi (частая причина обрывов на ноуте):

Диспетчер устройств → твой беспроводной адаптер → Свойства → вкладка Управление электропитанием → сними «Разрешить отключение устройства для экономии энергии».
Панель управления → Электропитание → Дополнительные параметры → Параметры адаптера беспроводной сети → Режим энергосбережения → Максимальная производительность (если есть такой пункт).
3. Сброс сетевого стека на ноуте (если ПК ок, ноут нет)
Открой cmd от имени администратора и по очереди:

netsh winsock reset
netsh int ip reset
ipconfig /flushdns
shutdown /r /t 0
После перезагрузки проверь Cursor снова.

4. DNS на ноуте (если на ПК всё ок)
Параметры → Сеть и Интернет → Wi‑Fi → твоя сеть → Изменить параметры IP → включи IPv4, DNS вручную: например 1.1.1.1 и 8.8.8.8.

5. VPN, прокси, антивирус
На ноуте отдельно проверь: нет ли VPN/прокси, которых нет на ПК. Временно отключи HTTPS-сканирование в антивирусе и проверь снова.

6. Cursor на слабом ПК
Обнови Cursor до последней версии.
Не держи открытыми огромные workspace и десятки расширений.
Если «падает» именно при долгих ответах — это часто память + диск, а не роутер.
Что прислать, если хочешь сузить причину до одной
Точная модель ноутбука и строка Wi‑Fi адаптера из Диспетчера устройств.
Скрин Память в Диспетчере задач во время сбоя (занято/свободно).
Сколько свободно на C:.
Проблема только в Cursor или и браузер «тупит» в те же моменты?
Так можно отличить сеть/драйвер от 4 ГБ ОЗУ и диска за один заход.

Если оба ping OK, а ассистент не отвечает → проблема чаще сессия/аккаунт/сервис, а не ваш интернет.

Если на стационарном ПК в той же сети всё стабильно, сеть/роутер/провайдер почти точно ни при чём. Тогда диагностика на ноуте сводится к 3 главным классам причин: сессия Cursor, локальные блокировки (VPN/Proxy/антивирус/фаервол), ресурсы ноутбука (ОЗУ/диск/энергосбережение Wi‑Fi).

Что делать, если повторится (быстрый алгоритм 3–5 минут)
Понять “это Cursor или весь ноут”
Если в момент “зависаний” тормозит и браузер/сайты → это ресурсы/драйвер/система.
Если тормозит только Cursor/чат → чаще сессия/блокировки/сам Cursor.

Перезапуск Cursor “чисто”
Закрыть Cursor → в Диспетчере задач завершить все процессы Cursor → открыть снова.

Переавторизация
Выйти из аккаунта Cursor → войти заново.

На время теста отключить мешающее
Отключить VPN/Proxy.
Если есть антивирус с HTTPS/Web‑сканированием — временно выключить и проверить.


Если проблема на ноуте повторяется регулярно (фикс, который чаще всего помогает)

Проверить ОЗУ/диск
Диспетчер задач → Производительность → Память: если 90–100% во время Cursor — будут таймауты/подвисания.
На диске C: держать 25–30 ГБ свободно минимум.
Файл подкачки: не отключать, лучше “управляется системой”.

Убрать энергосбережение Wi‑Fi
Диспетчер устройств → Сетевые адаптеры → ваш Wi‑Fi → Свойства → Управление электропитанием → снять “Разрешить отключение…”.
(Если есть) Электропитание → Доп. параметры → адаптер Wi‑Fi → Максимальная производительность.

Сброс сетевого стека ноутбука (если именно ноут “чудит”, а ПК нет)
В cmd от администратора:
netsh winsock reset
netsh int ip reset
ipconfig /flushdns
shutdown /r /t 0


Как “зафиксировать” причину в момент сбоя
Скрин Диспетчера задач → Память и Диск.
Вывод команд (чтобы отличить DNS/фильтрацию от остального): ping -n 4 github.com, nslookup github.com.
Текст ошибки из Cursor (если появляется).

Если проблема повторится — просто пришлите: (1) что именно происходит/какая ошибка, (2) скрин “Память/Диск”, (3) вывод ping github.com и nslookup github.com. По этому обычно можно сразу сказать, это “ОЗУ/диск”, “DNS/фильтр”, или “сессия/Cursor”.
